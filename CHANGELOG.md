## [Unreleased]

### Breaking changes

- **The server refuses to bind a non-loopback interface with no token (#71).** `npm run server` and a direct `startServer()` call now default to `127.0.0.1` (`AGENT_VIEWER_HOST`), not every interface. Setting `AGENT_VIEWER_HOST` to anything else (for example `0.0.0.0`) with no `AGENT_VIEWER_API_TOKEN` configured makes the process print one line to stderr and exit with code 1 (`OpenApiRefusedError`, `code: 'open_api_refused'`). Set a token, bind loopback, or set `AGENT_VIEWER_ALLOW_OPEN=1` to accept an open API anyway. The `agent-viewer` CLI and the Docker images are unaffected: they always run with a token.
- **A `token` or `api_key` query parameter never authenticates `/api/v1` or `/v1/logs`, in any mode, even when the value is correct (#71).** Such a request now gets `401 query_token_not_supported`. This also applies to webhook URLs that relied on it: a sender that can only set a URL (no headers) must sign with `AGENT_VIEWER_WEBHOOK_SECRET` instead. `EventSource` clients (which cannot send an `Authorization` header) now call the new `POST /api/v1/stream-tickets` first and open the stream with the single-use ticket it returns (`?ticket=`); `connectEventStream` in `@warlockcode/agent-viewer` does this automatically wherever `fetch` cannot stream a response body.
- **With no token configured and no `AGENT_VIEWER_ALLOW_OPEN=1`, `/api/v1` now rejects requests that do not look local (#71).** A request from a non-loopback remote address gets `403 open_api_loopback_only`; a non-loopback `Host` header gets `403 open_api_host_not_allowed`; an `Origin` header whose host is neither loopback nor listed in an explicit `AGENT_VIEWER_CORS_ORIGIN` gets `403 open_api_origin_not_allowed` (a bare `*` does not count as a list). A request with no `Origin` header (curl, the SDKs, the CLI) is unaffected, and an HMAC-signed webhook still works regardless of where it comes from. A reverse proxy in front of the server makes every request look local, so a proxied deployment still needs a token.

### Added

- **Usage ledger with server receive time** (#65, first item of the v0.4.0 milestone): a new `usage_ledger` table holds one append-only, typed row per accepted `llm.usage`/`llm.failed` event, written in the same SQLite transaction as the event, carrying `received_at` (the **server** clock, always equal to that event's `events.created_at`) and `occurred_at` (the client's own `timestamp`). Every number is copied, never computed: an unreported token kind, cost, currency or latency is `NULL`, a reported `0` stays `0`. A `usage_ledger_skips` table records why an accepted usage event produced no row instead: `duplicate` (same `(provider, requestId)`, same figures), `conflict` (same key, different figures, with `kept_event_id`) or `unparseable` (only reachable from the backfill). Neither table has a foreign key to `events`, so retention (#70) will be able to prune old events without deleting their ledger rows. `UPDATE usage_ledger` always fails (`usage_ledger is append-only`).
  - `GET /api/v1/events` now returns `receivedAt` on every event (both storage modes); `POST /api/v1/events` and the batch route echo `receivedAt` too, with a duplicate reporting the *original* acceptance time, never the retry's. A client-sent `receivedAt` is always ignored on ingest.
  - New `GET /api/v1/usage/ledger/status`: row counts by origin (`live`/`backfill`), legacy rows, skip counts and the oldest/newest receive time. Never a sum of tokens or cost (that is #66).
  - **Upgrade note:** the first start of a 0.4.0 server runs a one-time backfill over every `llm.usage`/`llm.failed` event already stored, paged by `rowid` so memory stays flat on a large database, and logs one progress line per page plus a final summary, for example `usage_ledger: scanned=1546 inserted=1530 duplicate=14 conflict=2 unparseable=0 (backfill)`. A backfilled row from a pre-0.4.0 server is marked `legacy_contract = 1`, which also resolves the 0.2.x "unknown reported as 0" ambiguity for cached/reasoning tokens (and, for legacy webhook rows only, input/output tokens) by storing those historical zeros as `NULL`. Every later restart repeats the same scan to catch up on any gap (for example after a temporary downgrade); in normal operation this finds nothing to do.
  - Memory mode gets its own independent ledger structures, capped by the new `AGENT_VIEWER_USAGE_LEDGER_MAX_ROWS` (default 100,000), never tied to `AGENT_VIEWER_MAX_EVENTS`'s much smaller event ring: evicting an event from the ring never removes its ledger row.
  - Reference: [docs/usage-ledger.md](docs/usage-ledger.md).
- **`POST /api/v1/stream-tickets` (#71)**: issues a short-lived (`AGENT_VIEWER_STREAM_TICKET_TTL_MS`, default 30 s, clamped to `[1000, 300000]`), single-use ticket for `EventSource` clients, capped at `AGENT_VIEWER_STREAM_TICKET_MAX` (default 1000) outstanding tickets at once (`429 stream_ticket_limit` past the cap). Requires the Bearer token; a ticket cannot mint tickets, and it only authenticates `GET /api/v1/events/stream`. A ticket minted under a token that is later rotated stops working, giving the operator a revocation path.
- `server/network.ts`: `isLoopbackHost`, `isLoopbackAddress`, `assertSafeBind` and `OpenApiRefusedError`, the single definition of "loopback" the server's bind guard and open-mode request guard both use.
- `server/stream-tickets.ts`: `createStreamTicketStore`, the in-memory, single-use ticket store behind `POST /api/v1/stream-tickets`.
- **Secret redaction module** (issue #68, first slice of the 0.4.0 secret redaction baseline): a new, pure, dependency-free `src/integrations/redaction.ts` with no runtime imports (type imports only), so the server, the portal and the library will all be able to import the exact same rule set once they are wired to it.
  - `BUILTIN_REDACTION_RULES` (`builtin-1`): provider API keys (Anthropic, OpenAI, Google, Hugging Face, Groq, Slack, Stripe, GitLab, npm, GitHub), AWS access keys and secret keys, Azure storage account keys, `Bearer` and `Basic` auth headers, JWTs, PEM private key blocks, connection string passwords and generic `key: value` / `key=value` secret assignments. Every rule tolerates a 60- or 140-character truncation as long as the minimum body survives, and a masked placeholder such as `********` is never treated as a secret.
  - `compileRedactionPolicy()` builds a policy from the built-ins plus optional operator configuration: `extra` patterns (validated name, flags, capture group and a 50ms-per-pattern / 250ms-total startup self-test against a bundled adversarial corpus), `disable` for documented false positives, and `ownSecrets` for the server's own tokens (labelled `own_secret`, minimum 8 characters). Every active rule is also checked for idempotence on its own marker at compile time. Any violation throws `RedactionConfigError` naming the offending pattern, so a misconfigured server fails closed instead of starting with a partial policy.
  - `redactText()` replaces matches with a deterministic `[REDACTED:<rule>]` marker (keeping, for example, `Bearer ` or `user:@host`) and is idempotent: redacting already-redacted text always reports `count: 0`.
  - `truncateKeepingMarkers()` cuts a string to a maximum length without ever splitting a marker in half.
  - `redactEvent()`, `redactDeep()` and `findSecretsInIdentifiers()` round out the module: event-level redaction that never touches `llm.usage` numeric fields or identifier keys (`provider`, `model`, `requestId`, `currency`, `costSource`, and the rest of the guarded list), an iterative deep-object string walker for arbitrary payloads, and an identifier guard that reports offending paths and rule names without ever returning the matched value.
  - New `tests/redaction.test.mjs` (94 cases, `node:test`): a true-positive and false-positive corpus per rule (built with runtime string concatenation, never literal secrets, so the repository stays clean for GitHub push protection and future gitleaks scanning), truncation, idempotency, determinism, the identifier guard, `own_secret`, extra-pattern validation (including a deliberately slow pattern that fails the startup budget), `disable`, the policy id hash, and loose-bound performance checks for a ~2KB event and a 1MB batch body.
  - **Deferred to follow-up PRs under the same issue**, per the issue's own suggested PR order (module, then server/store, then SDK/CLI/docs, then portal/library): wiring this module into the server's ingestion path (`server/redaction.ts`, the `ingestEvents` choke point, the `422 secret_in_identifier` rejection, `GET /api/v1/redaction/policy`, `/ready`), the `event_json`/`redaction_count` SQLite migration and store API changes, the `CanonicalEvent.redaction` contract field, the three `AGENT_VIEWER_REDACTION*` environment variables and CLI flags, the SDK `redactions` pass-through, and the portal "mask secrets" wiring (`useDisplayText`, the shield badge, the library `maskSecrets` prop). Landing the engine first, fully tested and reviewed on its own, keeps this change small enough to review and avoids touching `server/index.ts` while issue #71 is also in flight on that file.
- **OTLP metrics ingestion (`POST /v1/metrics`) and `http/protobuf` for both OTLP routes** (#73), building on the OTLP/HTTP logs receiver from #59. `/v1/metrics` stores Claude Code's `claude_code.token.usage` and `claude_code.cost.usage` counters as their own evidence (new `telemetry_metric_points`/`telemetry_meta` tables, migration 5), kept strictly apart from the ledger, the snapshot, SSE and every rollup: a metric point never becomes a canonical event. A keyed `HMAC-SHA256` series key (random secret, persisted in SQLite mode) deduplicates retries and tells series apart without ever being recoverable from a stored attribute. Delta and cumulative aggregation temporality are both resolved correctly, including counter resets, through `server/telemetry.ts` (`sumSeriesValue`, `sumTelemetryBySession`), covered by a property test against random sequences.
  - Both `/v1/logs` and `/v1/metrics` now accept `Content-Type: application/x-protobuf` (OTLP's default wire format for most real exporters), decoded by a new, small, zero-dependency reader (`server/otlp/protobufWire.ts`, `server/otlp/otlpProtobuf.ts`) built from the `opentelemetry-proto` v1 field-number table: no protobuf library was added, so the runtime dependency set stays at `express`, `lucide-react` and `zod`. A protobuf request gets a protobuf response, including `partialSuccess` and error bodies. gRPC is not supported.
  - `AGENT_VIEWER_TELEMETRY_MAX_POINTS` (default `100000`) bounds memory-mode storage of metric points; once full, further points are rejected through `partialSuccess`, never dropped silently. SQLite mode is bounded by disk, like the events table.
  - Deferred: `GET /api/v1/usage/reconciliation` (comparing the ledger's totals against these metrics) needs the usage ledger accessor from issue #65, which was still open when this shipped. `sumTelemetryBySession` is the metrics-side half that endpoint will consume once #65 lands.
  - Reference: [docs/otlp.md](docs/otlp.md).
- **Usage correlation and attribution fields** (#64): `llm.usage` and `llm.failed` accept six new optional payload fields through a shared `UsageCorrelationSchema` block: `traceId`, `parentId`, `toolCallId`, `meetingId`, `userId` and `tags`. All are opaque to Agent Viewer (no aggregation, no UI, never summed or grouped by the embeddable library), additive and optional, so every event that validated before still validates with the same output.
  - Each id field accepts 1 to 128 characters, no control characters and no leading or trailing whitespace (the exact ECMAScript `trim()` whitespace set); `tags` allows up to 20 items of 1 to 64 characters each, deduplicated in order after the 20-item limit is checked. `null` and absent both mean "not reported" and are omitted from the stored payload; an empty string is rejected, not silently accepted.
  - Reused automatically by the generic webhook's `usage` object (it already shares `LlmUsagePayloadSchema`), `parseEventLog` (JSONL import), the SSE stream and both the memory and SQLite stores: no storage migration needed.
  - The Python SDK's `usage()`, the new `llm_failed()` helper and the legacy `llm_usage()` accept the six fields as keyword-only arguments (snake_case), validate them locally with the same limits (`ValueError` naming the argument, `TypeError` for a wrong type), and count length in UTF-16 code units to match the server exactly. `tool_started`/`tool_completed`/`tool_failed` accept `tool_call_id`.
  - The TypeScript SDK's `usage()`, the new `llmFailed()` helper and the three tool helpers accept the same fields, validated locally with `AgentViewerError` (`issues` in the same `{ path, message }` shape the server returns).
  - The five example adapters (`openai-agents-adapter.ts`, `langgraph-adapter.ts`, `google-adk-adapter.ts`, `autogen-adapter.py`, `crewai-adapter.py`) forward the trace, parent and tool call ids their framework exposes, never inventing one, and never forward framework tags or metadata automatically.
  - `CORRELATION_ID_MAX_LENGTH`, `USAGE_TAGS_MAX`, `USAGE_TAG_MAX_LENGTH` and the `UsageCorrelation` type are exported from `@warlockcode/agent-viewer`. A 0.4.0 or later server is needed to keep these fields: an older server accepts the event and silently drops them.
  - See [docs/integration.md](docs/integration.md#correlation-and-attribution-fields-issue-64) for the full contract.
- **The live portal loads its history before subscribing to the stream** (#72), so a reload or a second tab opened mid-run restores the office and the token/cost figures from the server instead of starting at zero. On open, the portal fetches `GET /api/v1/snapshot` (reusing the rebuild path issue #54 already added for a resync) and, when the store holds more than the snapshot's own newest 100 events, pages further back with the new `beforeId` parameter of `GET /api/v1/events` up to `VITE_AGENT_VIEWER_HISTORY_LIMIT` (default `1000`, valid range 1 to 5000) so the activity timeline can go deeper; figures never depend on that extra depth, only the snapshot's own totals. Only after that does it subscribe to `GET /api/v1/events/stream`, resuming from the snapshot's own `lastEventId` through the library's existing `lastEventId` option. The top bar badge now reflects this as a `loading` / `subscribing` / `live` / `reconnecting` / `error` phase (`data-testid="live-phase"`, `data-phase`), with a retry control when the history fails to load; it previously only reacted to the arrival of an event.
- `GET /api/v1/events` now supports backward paging: a `beforeId` cursor (events stored strictly before it, in arrival order), `hasMore` and `nextBeforeId` in the response, so a client can walk the full stored history with no duplicates and no gaps on both the memory and the SQLite store.
- **`parseEventLog` reads an OTLP/JSON file** (#74), not only canonical JSONL: a pretty-printed OTLP export, or one request per line (an OpenTelemetry Collector `file` exporter). `resourceLogs` records convert to `llm.usage`/`llm.failed` events through the same Claude Code mapper the live `POST /v1/logs` receiver uses (now shared at `src/integrations/otlp/claudeCodeLogs.ts`, moved out of `server/` so the library can bundle it); a record with no usable timestamp or a required field missing is rejected and counted, never given the current time or a made-up figure. `resourceMetrics` is never replayed as calls (metrics are pre-aggregated counters): one clear issue per file explains why, pointing at the logs signal and at `POST /v1/metrics`. `resourceSpans` support is unchanged (not yet available). `EventLogParseIssue` gains optional `code` (`EventLogIssueCode`: `invalid-json`, `invalid-event`, `otlp-metrics-not-replayable`, `otlp-traces-not-supported`, `otlp-record-skipped`, `otlp-no-usage-records`) and `path`; `EventLogParseResult` gains an optional `otlp` summary (`signals`, `logRecords`, `converted`, `skipped`, `rejected`). An OTLP issue never sets `raw`, since a log record can carry sensitive text. The demo app now picks a localized `drop.*` message from the issue codes instead of always showing the generic "no events" text. Reference: [docs/event-log.md](docs/event-log.md#otlp-files).
  - `src/integrations/claudeCodeIdentity.ts` now hashes with a new pure-JS `sha256Hex` (`src/integrations/sha256.ts`) instead of `node:crypto`, so the shared OTLP mapper has no `node:*` import and stays bundleable for the browser; the digest is byte-identical to the previous `node:crypto`-based one, so every existing id (CLI hook, live OTLP receivers) is unchanged.

### Fixed

- **Release pipeline hardening**, a direct follow-up to the 0.3.0 release gate (#63): `.github/workflows/release.yml` no longer lets a tag "succeed" with nothing published.
  - The npm publish step now fails the job (instead of a silent `exit 0`) when `NPM_TOKEN` (or trusted publishing) is missing on a real release tag.
  - A new `pypi` job builds the sdist and wheel from `sdk/python/` with `python -m build`, checks them with `twine check`, installs the wheel in a clean venv and publishes to PyPI with `pypa/gh-action-pypi-publish` (trusted publishing, `pypi` environment).
  - A tag with an `-rc.N`, `-beta.N` or `-alpha.N` suffix (for example `v0.3.0-rc.1`) is now detected as a prerelease: every job still builds and checks everything, but nothing publishes to npm, PyPI or GHCR, and the GitHub release is created as a prerelease. The detection lives in `scripts/release-rules.mjs` and is exposed as the `release` job's `is_prerelease` output so every other job reads the same value.
  - The GHCR docker job now pushes only on a non-prerelease tag (it still builds both images on a prerelease, to verify they build) and only after npm and PyPI have finished.
  - The GitHub release notes are now the real `## [X.Y.Z]` section extracted from `CHANGELOG.md` via `--notes-file`, instead of the fixed text `"See CHANGELOG.md"`.
  - The version-alignment check now also fails when `sdk/python/pyproject.toml` disagrees with the tag, not only `package.json`.
  - New `tests/release-versions.test.mjs` and `tests/release-workflow.test.mjs` cover this logic (`node:test`), importing the shared `scripts/release-rules.mjs` rather than re-implementing it, and asserting on the workflow's actual job structure and shell scripts.

### Changed

- `GET /api/v1/events`'s `limit` is now clamped to `[1, 500]` (`Math.floor`, non-numeric or absent still gives the previous default of `100`); it was previously unbounded and unchecked.
- The SQLite event store now orders `GET /api/v1/events` by its durable arrival sequence (`seq`) alone, the same order the memory store and the SSE reconnect replay already use, instead of `timestamp` first. This only matters when events arrive with a non-monotonic `timestamp` (a backfilled batch, more than one runtime, a clock correction): before this change a `beforeId`/`afterId` cursor could disagree with the listed order in that case and a backward walk could duplicate or skip a row.
- **`parseEventLog` classifies its input by parsing, not by a substring test** (#74): a canonical JSONL line whose `summary` happens to contain the text `"resourceSpans"` now parses as JSONL instead of being misrouted to the OTLP branch. OTLP input now reports the real physical line count in `totalLines` (previously hard-coded to `1`), and a truncated pretty-printed OTLP document (for example cut off mid-export) now gives one `invalid-json` issue instead of one "Malformed JSON" issue per physical line.
- **The release pipeline no longer treats npm and PyPI as required.** The GitHub release (with the packed `.tgz`) and the GHCR Docker images are the actual release; npm and PyPI publishing are optional extras. The "Publish to npm" and "Publish to PyPI" steps are now `continue-on-error: true`: a missing `NPM_TOKEN` or unconfigured PyPI trusted publisher still prints a clear error annotation and shows as a failed step in the run, but no longer fails the job or blocks the GitHub release / Docker images from being created. Publishing to npm and PyPI for real is tracked separately as a future enhancement, not a release blocker.

## [0.3.0] - 2026-10-09

"Cifras ciertas" (true figures): the server, the portal, the CLI and the SDKs stop treating an unknown token count, cost or currency as zero, split cache reads from cache writes, add `llm.failed`, and Claude Code finally reports tokens through `install claude-code --telemetry`. First release published to npm, GHCR and (pending the owner's PyPI trusted-publisher setup) PyPI. The full semantics, field by field, are written down once in [docs/usage-semantics.md](docs/usage-semantics.md) ([español](docs/usage-semantics.es.md)); every section below links back to it instead of restating the rules. While the package is at 0.x, its API may still change between minor versions.

### Breaking changes

- **Snapshot usage block.** `GET /api/v1/snapshot` (and the new `GET /api/v1/usage`) no longer carries only a bare `totalTokens` / `totalCost`. It now also returns `usage: UsageSummary` (`server/usageAggregates.ts`): per `(currency, costSource)` cost buckets, a `sum`/`unreportedCount` pair per token kind, and the same breakdown by agent and by model. `totalTokens` and `totalCost` are kept for one minor as deprecated projections (removed in 1.0): `totalCost` is a number only when every successful call reported a cost in exactly one `(currency, costSource)` pair, and is `null` otherwise, instead of a sum across currencies.

  Before (0.2.x):
  ```json
  { "totalTokens": { "input": 1200, "output": 340, "cached": 0, "reasoning": 0 }, "totalCost": 0.42 }
  ```
  After (0.3.0), alongside the same (now honest) deprecated fields:
  ```json
  {
    "totalTokens": { "input": 1200, "output": 340, "cached": 0, "reasoning": 0 },
    "totalCost": null,
    "usage": {
      "total": {
        "calls": 2,
        "tokens": { "input": { "sum": 1200, "unreportedCount": 0 }, "output": { "sum": 340, "unreportedCount": 0 } },
        "byCurrency": [{ "currency": "USD", "costSource": "provider-reported", "amount": 0.3, "calls": 1 }],
        "costUnknownCount": 1
      }
    }
  }
  ```
  Migration: read `usage.total` (or `GET /api/v1/usage`) instead of `totalTokens`/`totalCost`; see [docs/usage-semantics.md](docs/usage-semantics.md) section 2 for every field.
- **`PATCH /api/v1/agents/:agentId` allow-list.** Only descriptive profile and status fields are accepted (`name`, `roleTitle`, `provider`, `model`, `status`, `statusText`, `workspace`). `tokensInput`, `tokensOutput`, `cachedTokens`, `reasoningTokens`, `cost` and any other unlisted key are rejected with `400 validation_failed` (`issues[].path` names the field), instead of silently changing spend. Migration: report usage with an `llm.usage` event through `POST /api/v1/events`, or the SDK `usage()` / `agent.usage(...)` helper.
- **Contract nullish fields.** `llm.usage` (and `llm.failed`) no longer default `cachedTokens` or `reasoningTokens` to `0`: an omitted or `null` value now stays `null`/absent instead of becoming a zero that looked like "the provider reported zero". New `cacheReadTokens` and `cacheWriteTokens` replace the deprecated `cachedTokens` (kept as an alias; a differing value in both is rejected). New `llm.failed` event type (canonical event count: 22 to 23).

  Before: `{ "inputTokens": 500, "outputTokens": 120 }` meant "cached and reasoning tokens are zero".
  After: the same payload means "cached and reasoning tokens were not reported"; a provider that truly billed zero cached tokens must send `"cacheReadTokens": 0` explicitly.

  Migration: readers of stored or exported events must handle `null`/absent as "unknown", not "zero".
- **SDK `costSource` default.** Passing a `cost` with no `costSource` no longer sends `"provider-reported"`; it now sends `"unknown"` and prints one warning per client instance. `currency` and a task id are newly accepted. Migration: pass `cost_source="provider-reported"` (Python) or `costSource: 'provider-reported'` (TypeScript) when the cost really came from the provider, and pass `currency`.
- **Totals no longer include `PATCH` amounts or unknown-as-zero.** A figure the 0.2.x snapshot showed (built from `PATCH`-edited numbers and zero-filled unknowns) can differ from the 0.3.0 figure for the exact same stored data; the 0.3.0 number is the correct one. See [docs/usage-semantics.md](docs/usage-semantics.md) for how to reconcile it against a provider invoice.
- **Webhook usage validation is now stricter.** `usage` blocks without required fields (`provider`, `model`, `inputTokens`, `outputTokens`) are rejected with `400 validation_failed`. Empty usage objects (`{}`) are now rejected, not accepted as zero-filled events. Usage with an unknown `costSource` is accepted as an `unknown` cost source, not silently mapped to an assumed value.
- **Ingestion behavior change:** a client that reuses an event id for different content used to get `200 duplicate` and now gets `409 conflicting_duplicate`. The new event is still not stored, so totals do not change; the difference is that the loss is now visible. Batches keep answering `202` and report the item as `status: "conflict"`.
- Raw HTTP clients that retry by rebuilding the body with a fresh `timestamp` now get `409` on the retry, because `timestamp` is part of the event. A retry must resend the identical event. The SDKs are not affected: they build each event once and resend the same object.
- Retries across the upgrade: an event stored by 0.2.x with a default the 0.2.x validator filled in (for example `cachedTokens: 0`) has a different fingerprint than the same event validated by 0.3.0, so a retry of it after upgrading gets `409`. This fails closed: the stored row stays and nothing is counted twice.
- The Claude Code hook gives a tool event a stable id but the `timestamp` of each hook run, so a hook that fires twice (installed in both user and project settings) now reports the second copy as `conflict` instead of `duplicate`. The hook still exits 0 and the office keeps the first copy; the count shows in `/ready`.
- A 0.3.0 SDK needs a 0.3.0 server: a 0.2.x server rejects `llm.failed` and drops `cacheReadTokens` and `cacheWriteTokens`.

### Added
- SSE reconnect now replays every missed event or sends an explicit resync, never a silent partial replay (issue #54). New `AGENT_VIEWER_SSE_REPLAY_MAX` (default `10000`, `0` means any reconnect that missed something always resyncs) bounds how many missed events a reconnect replays in full; past it, or when the cursor is unknown (never stored, evicted in memory mode, or lost after a memory-mode restart), the server sends a named `resync` frame (`reason`: `cursor_unknown`, `gap_too_large` or `buffer_overflow`, `missed` as a count or `null` when truly unknown, never `0`) instead of event frames, and keeps the connection open and streaming live events afterward so older clients keep working. A full replay ends with a named `replayed` frame (`replayed`, `lastEventId`). `GET /health` gains `sse: { replayMax, replaysSinceStart, eventsReplayedSinceStart, resyncsSinceStart }`. `connectEventStream` gains `lastEventId` (resume from a cursor, typically `snapshot.lastEventId`), `onResync` and `onReplayed` options, a new `resyncing` `RealtimeStatus`, and `resyncCount()` on the returned connection. The demo app rebuilds its live office from `GET /api/v1/snapshot` on a resync through the new `rebuildFromSnapshot` helper (`src/integrations/snapshotRebuild.ts`), shows the server's own usage totals (never re-added from the snapshot's 100 events) and a dismissible notice in English and Spanish. See [docs/integration.md](docs/integration.md#reconnect-replay-and-resync-issue-54) and [docs/library.md](docs/library.md#reconnect-replay-and-resync-issue-54).
- Golden reconciliation suite (`npm run test:golden`, issue #62): one hand-checked fixture (`tests/fixtures/reconciliation/`, mixed currencies, a missing cost, a missing currency, missing cache tokens, a duplicate id, a conflicting duplicate, a repeated `requestId`, a failed call) run through the memory store, the SQLite store across a restart, the portal reducer and the embeddable library's `summarizeUsage`, asserting all four reach the same figures. Runs as its own CI step, right after typecheck, and fails on the field and the path that diverged. Ships with an independent reference reducer that cross-checks the hand-worked expected figures. Deferred to a follow-up: the HTTP routes (including signed webhook retries and the `PATCH` rejection path), memory eviction, and a `library-privacy` Vitest suite; none are blocked on a missing dependency, see the fixture's `README.md`.

### Fixed
- SQLite-backed server state (agents, runtimes, sessions, tasks, meetings and usage totals) no longer resets to empty on restart. An upgrade that changes the reducer recomputes the whole history with the new reducer at the next startup; that is intended, not a bug.
- A retried `llm.usage` or `llm.failed` event (or any event id) that had already fallen off the memory-mode retained window is no longer double counted. Before this fix, eviction deleted the id from the dedup index too, so a late retry (a timeout retry, an SDK queue flush, a webhook redelivery) was accepted as new: its tokens and cost were added a second time to the agent and global totals, and it was broadcast again. The fix only changes behavior for an id that had already fallen out of the retained window; an ordinary retry of a still-retained event was already deduplicated correctly.
- Model Ops no longer shows simulated calls as if they were real usage. - A v1 demo session (0.2.x) saved with a `evt-burst-*` simulated event now migrates to v2 on load: the event is removed and its token/cost values are subtracted from the agent and from the office totals, clamped at 0. Sessions already evicted past the stored event cap cannot be reversed and keep their old counters, a known limitation. A v2 session loads unchanged.
- Webhook usage retries no longer double-count. The generic webhook now uses deterministic event IDs derived from idempotency keys, so identical retries are deduplicated inside the store. Same delivery with same `Idempotency-Key` header, body `idempotencyKey` field, or signature gets a `200` duplicate response instead of `202` new events. ## [0.2.0] - 2026-10-08

First release of the embeddable library as the package `@warlockcode/agent-viewer`. Until it is published on npm (coming soon), it is installed from the GitHub release asset. While the package is at 0.x, its API may still change between minor versions. The guide is in [docs/library.md](docs/library.md) ([español](docs/library.es.md)).

### Added
- Library build: `npm run build:lib` writes ES modules and TypeScript declarations to `dist-lib/`. The package is ESM only, React and React DOM `^19` are peer dependencies, and `lucide-react` and `zod` are its only runtime dependencies. Modules stay in separate files so bundlers can drop what a host does not import.
- `<AgentOffice>` driven only by events: the office is derived from the `events` prop (append for live activity, pass a slice of a recorded run for replay), with optional `agents` profiles (name, role title, team, workspace, avatar color), controlled selection and a configurable bubble duration.
- Professional mode, the default: the office shows only what the events say, with no ambient life, no invented lines, no hidden second floor and no sounds. `mode="showcase"` adds simulated office life, marked as simulated.
- `OfficeStore` and `buildOfficeSnapshot` to derive the office from events without rendering it (servers, tests, exports).
- `useEventReplay` and the optional `ReplayControls` to replay a run at its original pace, with seek and speed.
- Injectable texts: `locale`, `messages` and `t` props, built-in English and Spanish catalogs (`OFFICE_MESSAGES`), and `createOfficeTranslator`, `formatMessage`, `builtInMessages` and `isOfficeMessageKey`. A host `t` wins when it returns a value, then `messages`, then the built-in catalog of the locale, then English.
- Usage display rules: `showUsage` shows only the figures the host passes in `usage` (`total` and `byAgent`), and a missing value is shown as "unknown", never as zero. Helpers `formatUsage`, `formatTokens` and `formatCost`, plus the opt-in `summarizeUsage`, which only adds up reported figures and never prices tokens.
- Isolated CSS in `@warlockcode/agent-viewer/style.css`, imported by the host: every class starts with `av-`, there is no reset and no global selector, the theme lives in `--av-*` custom properties with zero specificity, and no external fonts are loaded.
- Accessibility: a live list of agents and their statuses that opens on keyboard focus and selects agents with the keyboard, a labeled canvas, toolbar and replay controls, visible focus, and no animation under `prefers-reduced-motion`.
- Message kinds in the event contract (`MESSAGE_KINDS`, `isMessageKind`): `statement`, `proposal`, `question`, `answer`, `objection`, `critique`, `agreement`, `summary` and `decision`. `meeting.message` `type` uses them, `agent.message.sent` accepts an optional `kind`, and speech bubbles show the kind in their header.
- Optional `currency` (ISO 4217 code) in the `llm.usage` payload.
- `CanonicalEventInput` and `LegacyEventType` types, and `EVENT_TYPE_ALIASES` in the public exports.
- `computeReplaySchedule`, and new `recordReplay` options: `agents`, `mode`, `maxGapMs`, `tailMs`, `maxDurationMs`, `locale`, `messages`, `t` and `usage`.

### Changed
- Repository layout: community files in `.github/`, Docker files in `docker/`, `.env.example` in `server/`, the Spanish README in `docs/`, one `vite.config.ts` for the app, the library and the tests.
- `AGENT_VIEWER_API_TOKEN` is the API token variable; `AGENT_VIEWER_API_KEY` still works as a deprecated alias.
- New README in English and Spanish with current screenshots and GIFs.
- Two offices on the same page never share state. The library uses no `localStorage`, no timers that invent data and no global keyboard shortcuts, and nothing runs on import.
- `recordReplay` draws on its own offscreen canvas, keeps the pacing of the original run, and never computes usage: the title and the usage figures appear only when passed.
- The `workspace` of an agent profile is its home: a new agent appears at its desk, and returns there after a meeting.
- The demo app (`npm run dev`) keeps working as before and builds separately with `npm run build`.

### Fixed
- `package-lock.json` now includes every platform binary, so `npm ci` works on a clean checkout on macOS, Linux and Windows.
- OTLP import removed: it loaded a module that did not exist. `parseEventLog` now reports that OTLP traces are not supported yet.
- Video export: `recordReplay` passed a canvas where the renderer expected a 2D context, so it failed on the first frame.
- An unknown `workspace` value in an event no longer crashes the engine; it is ignored.

- Server hardening: rate limiting runs before authentication; tokens are compared in constant time; signed webhooks cannot be replayed inside the timestamp window; without a webhook secret, webhooks need the API token; the generic webhook rejects payloads that map to no known event; `PATCH /api/v1/agents/:id` keeps the path id and rejects unknown statuses.
- The SQLite store honors `afterId` on reconnect and keeps the full event (with a migration for older databases).
- `npm run dev:full` starts the office in live mode, so events sent to the server appear right away.
- The Python SDK installs with `pip install ./sdk/python` (the wheel was empty before) and has no unused dependencies.
- Docker: the viewer image is built with the API URL, so it connects to the API; the API is the default target.
- Speech bubbles always show the message kind, use the full speaker name, are opaque and readable in the light theme, and real messages are never labeled as simulated. Labels on screens, desks and plaques fit their surface.

### Removed
- `metadata.json`: nothing in the repository referenced it.

### Breaking changes
Compared with the previous `AgentOffice` API, which was never published:
- `mode` accepts `professional` (default) or `showcase`. The values `live`, `demo` and `replay` are gone.
- The built-in drag and drop of log files, the replay bar and the video export button were removed from `<AgentOffice>`. Use `parseEventLog`, `useEventReplay` with `ReplayControls`, and `recordReplay` instead.
- `showUsage` defaults to `false`, and the figures come only from the new `usage` prop.
- `agents` takes `AgentProfile` objects (identity only) instead of full agent state; what agents do comes from `events`.
- The `replayEvents`, `activeMeetingId` and `onVideoExport` props were removed, and `SessionReplayPlayer` is no longer exported.
- `recordReplay` no longer accepts a `canvas`, `showUsage` defaults to `false`, and there is no default title.
