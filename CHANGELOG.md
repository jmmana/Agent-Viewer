## [Unreleased]

### Added

- **Crew asset recovery audit (#115)**: reconcile PR #43 and #162-164 revisions, the preserved 53-asset bank and reference, three showroom layout hashes, vector-study classification, independent-runtime evidence and unverified local work. Correct the historical migration matrix without approving prototype art or merging the legacy skin.

- **Named API keys and submitter identity (issue #107, v0.8.0 milestone)**: `AGENT_VIEWER_API_TOKEN` is now the "bootstrap" credential; `POST /api/v1/keys` creates additional named, independently revocable keys (`avk_<12 hex id>.<43 char secret>`, stored only as a SHA-256 hash, the full token shown exactly once), `GET /api/v1/keys`/`/:id` list or inspect them (`status`, `eventCount`, `firstEventAt`, `lastEventAt`), `POST /api/v1/keys/:id/revoke` revokes one (idempotent, never deletes the row), and `GET /api/v1/whoami` reports the identity of the current credential. Every physically stored event (and its usage-ledger row) now records `submitter_id` with a real identity (a key's id, `bootstrap`, `webhook`, or `anonymous`), reusing the column issue #105's hash chain already added and hashes, so rewriting an attribution is still detected. `GET /api/v1/events` exposes it as `submittedBy` (`null` for a pre-upgrade row, never back-filled), accepts `?submittedBy=` as a filter, and hides new internal `audit.key.created`/`audit.key.revoked` trail events by default (`includeAudit=true` or an explicit `type` filter shows them); these two types are rejected from `POST /api/v1/events`/`/events/batch` like any other unrecognized type. New CLI `agent-viewer keys create|list|revoke|whoami` (requires `AGENT_VIEWER_STORAGE=sqlite`); new SDK `whoami()` in both the TypeScript (`packages/sdk`) and Python SDKs, surfacing `key_revoked`/`key_expired` error codes without retrying them. Named keys have the same full read/write access as the bootstrap token in this item; role-based scopes and a read-only auditor role are issue #108. New `docs/api-keys.md`.
- **Scoped API keys and a read-only auditor role (issue #108, v0.8.0 milestone)**: every named key (issue #107) now carries `ingest`/`read`/`audit`/`admin` scopes (`admin` implies the other three, `audit` implies `read`); a new default-deny policy table (`server/auth/routePolicy.ts`) maps every `/api/v1` route to the scope it needs, enforced by one middleware so a new route can only come out stricter than intended, never more open. The bootstrap token (`AGENT_VIEWER_API_TOKEN`) and open mode (no token configured) both resolve to an implicit `admin` principal, so nothing changes for a deployment that never creates a named key. `403 insufficient_scope` (with a `WWW-Authenticate` header) is now distinct from `401 unauthorized`, checked before body validation. New `GET /api/v1/auth/whoami`; `POST`/`PATCH /api/v1/keys` accept `scopes`. Privilege-escalation guards: only `admin` can create keys or change scopes, a key can never change its own scopes, the bootstrap token's scopes can't be set, and the last active named admin key can't be revoked or demoted while no bootstrap token is configured (`409 last_admin`). OTLP ingestion (issue #59/#73/#97) requires `ingest` the same way. New migration 20 (`api-key-scopes`); existing #107 keys backfill to `["ingest"]`, least privilege. New `tests/api-key-scopes.test.mjs`. Deferred, documented as known gaps: closing an open SSE connection when its key is revoked or expires, `submittedBy` on SSE reconnect-replay frames, and `submittedBy` as a rollup/export dimension.
- **Hash chain over stored events (issue #105, v0.8.0 milestone, first item of the formal-audit theme)**: every SQLite-stored event now joins a SHA-256 hash chain, written inside the same transaction as its insert, so an edit, deletion or reordering of a chained row changes a hash that every later row already committed to. New pure module `server/chain.ts` (`canonicalize`, `eventHash`, `checkpointHash`, `UnchainedDigest`), a JSON Canonicalization Scheme (RFC 8785) implementation with golden test vectors (`tests/fixtures/chain-vectors.json`) for cross-language verification. New migration 17 (`event-hash-chain`): `events.prev_hash`/`hash`/`submitter_id` columns (reusing the existing `seq` column as the chain's position), a `chain_checkpoints` table recording a one-time `genesis` checkpoint over every pre-chain row (a single digest, not fabricated per-row hashes) and a `resume` checkpoint if an older server appends unchained rows after an upgrade, and a defense-in-depth `events_immutable` trigger. New read-only `GET /api/v1/audit/chain` endpoint, `?include=chain` on `GET /api/v1/events`, and an optional `chain` receipt on accepted ingestion responses (SQLite mode only). `submitter_id` is recorded on every physically stored row, derived from how the request authenticated (shared token, open API, webhook HMAC, or the request behind a server-generated event), never from token material. Memory mode is explicitly not tamper-evident (`GET /api/v1/audit/chain` reports `enabled: false`, logged once at startup). New `docs/audit-chain.md` documents the format, the genesis/resume checkpoint mechanics, and the honest scope of the guarantee (not a defense against a consistent rewrite by someone with full file write access, without an external anchor; #106 adds signed checkpoints for that). New `scripts/bench-ingest.ts` (not part of CI) measures sequential ingestion throughput. Verifying the chain, signed checkpoints, named ingestion keys, scoped keys, chain-compatible retention and the offline audit bundle are separate items (#106 to #111).
- **Chain-walk verifier and `GET /api/v1/audit/verify` (issue #106, first sub-issue, v0.8.0 milestone)**: walks the #105 hash chain in one read-only pass (a separate `DatabaseSync` connection from the writer's, paged, yielding between pages) and reports the first broken link. New pure module `server/audit/verify.ts` (`verifyChain`), reused unchanged by the CLI (#388) and extended by #387's checkpoint verification. Detects `hash_mismatch` (edited content), `link_mismatch` (a row deleted, inserted, reordered, or the first chained row's link to the genesis checkpoint tampered with), `unparseable_event`, `column_mismatch` (an indexed column edited directly, bypassing `event_json`; the message never names the value) and `missing_hash` (a row past every checkpoint's coverage with no hash). Legacy/unchained rows are counted in `chain.unchained` with a `legacy_rows` warning, not individually walked. New migration 18 (`audit-meta`): a generic key/value table whose only row today is a random `instanceId`, so a future signed checkpoint (#387) can be pinned to the database it came from. `SQLiteEventStore` gains `getDatabasePath()` (mirroring the existing `getDatabaseHandle()`), used by the new route to open its own connection. In memory mode (and on a database whose schema predates migration 17), the route answers the same `{ enabled: false, ... }` shape `GET /api/v1/audit/chain` already uses, not a `409`. There are no signed checkpoints yet, so `scope=recent` always behaves like `full` and a *consistent* rewrite is undetectable by design (the `no_checkpoints` warning says so). `docs/audit-chain.md` gains a "Verification" section; `README.md`/`docs/README.es.md` gain the route row. New `tests/audit-verify.test.mjs` (17 cases: every `BreakKind`, an empty chain, legacy-row upgrades, a truncated-migrations database, page-size independence, and the HTTP route's auth/scope-validation/memory-mode/in-flight-dedup behavior). Split off per `.claude/agent-policy.md`'s size rule: the signing/checkpoint infrastructure (#387) and the `agent-viewer verify` CLI command (#388) are separate sub-issues of #106.

## [0.7.0] - 2026-10-12

"Captura automática e interoperabilidad" (automatic capture and interoperability): an OTLP/HTTP GenAI traces
receiver and file import, packaged LangGraph and OpenAI Agents SDK adapters tested against the real
frameworks in CI, a durable local queue in both SDKs, and a Prometheus `/metrics` export (core endpoint,
ledger-derived families, in-process ingestion counters, optional OTLP metrics push).

### Upgrading

Purely additive: no breaking change to the event contract, the HTTP API, or the embeddable library's props.
Every new setting defaults to off or to its existing behavior, so an existing deployment needs no
configuration change to keep working.

- The SDK durable queue (Python `spool_dir=...`, TypeScript `spoolDir`/`AGENT_VIEWER_SPOOL_DIR`) is opt-in:
  without it, both SDKs behave exactly as before (an unrecovered transient failure still raises/throws).
- `GET /metrics` is opt-in (`AGENT_VIEWER_METRICS=1`, CLI `--metrics`); unset, the route answers `404`
  exactly like before this release. See [docs/metrics.md](docs/metrics.md) for every new environment
  variable it reads.
- The OTLP traces receiver (`POST /v1/traces`) and file import share the existing OTLP auth, rate limit and
  size-limit settings already in place for `/v1/logs`/`/v1/metrics`; no new required variable.
- `examples/openai-agents-adapter/` is removed (dead code since issue #361); import
  `@warlockcode/agent-viewer-openai-agents` instead if anything in your own tree still referenced that path
  (see the Removed section below).

### Added

- **Durable local queue in the Python SDK (#101, v0.7.0 milestone)**: optional, bounded, on-disk spool (`spool_dir=...`, stdlib `sqlite3` only, no third-party dependency) so a transient failure (connection down, reset, timeout, `408`, `429`, any `5xx`) after the normal retries never raises into the host agent. Events are written to disk with their original `id` and `timestamp` and replayed in enqueue order once the server returns, through `POST /api/v1/events/batch`, so the server's own idempotency by `id` keeps totals honest. New `AgentViewer` arguments (`spool_dir`, `spool_max_events`, `spool_max_bytes`, `spool_overflow`, `spool_batch_size`, `spool_background`, `spool_probe_interval`, `spool_max_probe_interval`) and methods (`flush()`, `spool_stats()`, `spool_rejected()`, `close()`, usable as a context manager, plus an `atexit` final flush). A size cap evicts the oldest non-usage events before usage events (`drop_oldest`, the default) or refuses the new event (`drop_newest`); every drop and every server-side rejection is counted in `SpoolStats`, never silently lost, and the spool never sums, prices or defaults usage (a missing `cost` stays absent, never `0`). Also fixes transient-failure classification with the spool disabled: a raw `OSError`/`http.client.HTTPException` and HTTP `408` are now retried instead of escaping or failing immediately. New `docs/sdk-queue.md` (shared contract with the TypeScript SDK, #102) and `tests/fixtures/sdk-queue-scenarios.json` (shared test vectors). New `tests/test_python_sdk_spool.py` (34 tests: outages, restart persistence, overflow matrix, poison events, `413`/`429`/`401` handling, corrupt/newer-schema spool files, permissions, fork safety, a seeded randomized concurrency test). CI now runs both Python SDK test files and adds a Python 3.9 job to exercise the SDK's declared minimum version.

## [0.4.0] - 2026-10-09

- **The server refuses to bind a non-loopback interface with no token (#71).** `npm run server` and a direct `startServer()` call now default to `127.0.0.1` (`AGENT_VIEWER_HOST`), not every interface. Setting `AGENT_VIEWER_HOST` to anything else (for example `0.0.0.0`) with no `AGENT_VIEWER_API_TOKEN` configured makes the process print one line to stderr and exit with code 1 (`OpenApiRefusedError`, `code: 'open_api_refused'`). - **With no token configured and no `AGENT_VIEWER_ALLOW_OPEN=1`, `/api/v1` now rejects requests that do not look local (#71).** A request from a non-loopback remote address gets `403 open_api_loopback_only`; a non-loopback `Host` header gets `403 open_api_host_not_allowed`; an `Origin` header whose host is neither loopback nor listed in an explicit `AGENT_VIEWER_CORS_ORIGIN` gets `403 open_api_origin_not_allowed` (a bare `*` does not count as a list). A request with no `Origin` header (curl, the SDKs, the CLI) is unaffected, and an HMAC-signed webhook still works regardless of where it comes from. A reverse proxy in front of the server makes every request look local, so a proxied deployment still needs a token.

- **`GET /api/v1/usage/rollup`** (#66, v0.4.0 milestone), the auditable read API over the usage ledger from #65: grouped sums for a question such as "how much did agent X spend with model Y this week", built to reconcile with a provider invoice.

An unknown parameter, dimension or enum value, more than 3 dimensions, `from >= to`, an offset-less date-time, or more than 100 values in one filter all return `400 invalid_filter` with a per-field `issues` array.

A `null` cost counts in `unknownCostCalls` instead of a sum. Each of the five token kinds (`input`, `output`, `cacheRead`, `cacheWrite`, `reasoning`) reports `sum: null` (never `0`) when nobody reported it, with `reportedCalls`/`unreportedCalls` always adding up to `calls.total`. `llm.failed` rows count in `calls.failed`. - **Retention baseline: scheduled purge of events and the usage ledger, with `GET /api/v1/admin/retention`** (#70): two independent windows, `AGENT_VIEWER_RETENTION_DAYS` (raw `events`) and `AGENT_VIEWER_USAGE_RETENTION_DAYS` (the usage ledger, defaults to keep forever), both measured by the **server** receive time, never the client's `timestamp`. ## [0.3.0] - 2026-10-09

"Cifras ciertas" (true figures): the server, the portal, the CLI and the SDKs stop treating an unknown token count, cost or currency as zero, split cache reads from cache writes, add `llm.failed`, and Claude Code finally reports tokens through `install claude-code --telemetry`. First release published to npm, GHCR and (pending the owner's PyPI trusted-publisher setup) PyPI. The full semantics, field by field, are written down once in [docs/usage-semantics.md](docs/usage-semantics.md) ([español](docs/usage-semantics.es.md)); every section below links back to it instead of restating the rules. While the package is at 0.x, its API may still change between minor versions.

### Breaking changes

- **Snapshot usage block.** `GET /api/v1/snapshot` (and the new `GET /api/v1/usage`) no longer carries only a bare `totalTokens` / `totalCost`. It now also returns `usage: UsageSummary` (`server/usageAggregates.ts`): per `(currency, costSource)` cost buckets, a `sum`/`unreportedCount` pair per token kind, and the same breakdown by agent and by model. `totalTokens` and `totalCost` are kept for one minor as deprecated projections (removed in 1.0): `totalCost` is a number only when every successful call reported a cost in exactly one `(currency, costSource)` pair, and is `null` otherwise, instead of a sum across currencies.

  Before (0.2.x):
  ```json
  { "totalTokens": { "input": 1200, "output": 340, "cached": 0, "reasoning": 0 }, "totalCost": 0.42 }
  ```
  After (0.3.0), alongside the same (now honest) deprecated fields:
  ```json
  {
    "totalTokens": { "input": 1200, "output": 340, "cached": 0, "reasoning": 0 },
    "totalCost": null,
    "usage": {
      "total": {
        "calls": 2,
        "tokens": { "input": { "sum": 1200, "unreportedCount": 0 }, "output": { "sum": 340, "unreportedCount": 0 } },
        "byCurrency": [{ "currency": "USD", "costSource": "provider-reported", "amount": 0.3, "calls": 1 }],
        "costUnknownCount": 1
      }
    }
  }
  ```
  Migration: read `usage.total` (or `GET /api/v1/usage`) instead of `totalTokens`/`totalCost`; see [docs/usage-semantics.md](docs/usage-semantics.md) section 2 for every field.
- **`PATCH /api/v1/agents/:agentId` allow-list.** Only descriptive profile and status fields are accepted (`name`, `roleTitle`, `provider`, `model`, `status`, `statusText`, `workspace`). `tokensInput`, `tokensOutput`, `cachedTokens`, `reasoningTokens`, `cost` and any other unlisted key are rejected with `400 validation_failed` (`issues[].path` names the field), instead of silently changing spend. Migration: report usage with an `llm.usage` event through `POST /api/v1/events`, or the SDK `usage()` / `agent.usage(...)` helper.
- **Contract nullish fields.** `llm.usage` (and `llm.failed`) no longer default `cachedTokens` or `reasoningTokens` to `0`: an omitted or `null` value now stays `null`/absent instead of becoming a zero that looked like "the provider reported zero". New `cacheReadTokens` and `cacheWriteTokens` replace the deprecated `cachedTokens` (kept as an alias; a differing value in both is rejected). New `llm.failed` event type (canonical event count: 22 to 23).

  Before: `{ "inputTokens": 500, "outputTokens": 120 }` meant "cached and reasoning tokens are zero".
  After: the same payload means "cached and reasoning tokens were not reported"; a provider that truly billed zero cached tokens must send `"cacheReadTokens": 0` explicitly.

  Migration: readers of stored or exported events must handle `null`/absent as "unknown", not "zero".
- **SDK `costSource` default.** Passing a `cost` with no `costSource` no longer sends `"provider-reported"`; it now sends `"unknown"` and prints one warning per client instance. `currency` and a task id are newly accepted. Migration: pass `cost_source="provider-reported"` (Python) or `costSource: 'provider-reported'` (TypeScript) when the cost really came from the provider, and pass `currency`.
- **Totals no longer include `PATCH` amounts or unknown-as-zero.** A figure the 0.2.x snapshot showed (built from `PATCH`-edited numbers and zero-filled unknowns) can differ from the 0.3.0 figure for the exact same stored data; the 0.3.0 number is the correct one. See [docs/usage-semantics.md](docs/usage-semantics.md) for how to reconcile it against a provider invoice.
- **Webhook usage validation is now stricter.** `usage` blocks without required fields (`provider`, `model`, `inputTokens`, `outputTokens`) are rejected with `400 validation_failed`. Empty usage objects (`{}`) are now rejected, not accepted as zero-filled events. Usage with an unknown `costSource` is accepted as an `unknown` cost source, not silently mapped to an assumed value.
- **Ingestion behavior change:** a client that reuses an event id for different content used to get `200 duplicate` and now gets `409 conflicting_duplicate`. The new event is still not stored, so totals do not change; the difference is that the loss is now visible. Batches keep answering `202` and report the item as `status: "conflict"`.
- Raw HTTP clients that retry by rebuilding the body with a fresh `timestamp` now get `409` on the retry, because `timestamp` is part of the event. A retry must resend the identical event. The SDKs are not affected: they build each event once and resend the same object.
- Retries across the upgrade: an event stored by 0.2.x with a default the 0.2.x validator filled in (for example `cachedTokens: 0`) has a different fingerprint than the same event validated by 0.3.0, so a retry of it after upgrading gets `409`. This fails closed: the stored row stays and nothing is counted twice.
- The Claude Code hook gives a tool event a stable id but the `timestamp` of each hook run, so a hook that fires twice (installed in both user and project settings) now reports the second copy as `conflict` instead of `duplicate`. The hook still exits 0 and the office keeps the first copy; the count shows in `/ready`.
- A 0.3.0 SDK needs a 0.3.0 server: a 0.2.x server rejects `llm.failed` and drops `cacheReadTokens` and `cacheWriteTokens`.

The hook never blocks Claude Code: it writes nothing to stdout, always exits 0, and stops within 400 ms when the office is down. `agent-viewer install claude-code` and `uninstall claude-code` edit only `<project>/.claude/settings.local.json`, after showing the change and asking. Each handler sets a 1 second `timeout`, so `SessionEnd` never delays Claude Code's exit. Installing twice changes nothing and says so; the file is written atomically and only if it did not change while the prompt waited; uninstall keeps a settings file or `.claude/` folder that existed before install (a small record in `~/.agent-viewer` notes what install created). Guide: [docs/claude-code.md](docs/claude-code.md).
- Docker image on GitHub Container Registry, published by the release workflow on every `v*` tag: `ghcr.io/jmmana/agent-viewer` (office and API in one container, new default `app` target of `docker/Dockerfile`) and the `-api` tags (API only). Multi-architecture (amd64, arm64), non-root, with a health check. Flags passed to `docker run IMAGE ...` are added to the defaults instead of replacing them, and `PORT` sets the port. - Canonical event `llm.failed` for one failed model call attempt: `provider`, `model`, `errorKind` (one of `LLM_ERROR_KINDS`, default `unknown`), `httpStatus`, `retryable`, `requestId`, `providerErrorCode` and `latencyMs`, plus tokens and cost only when the provider billed the attempt (none defaults to 0). It has no free-text error field on purpose. The server stores, lists and streams it and registers an unseen agent from it, but it never changes token or cost totals; the office only stores the agent's provider and model and never changes its status. Mapping guide in [docs/integration.md](docs/integration.md).
- `llm.usage` fields `cacheReadTokens` (tokens served from the prompt cache) and `cacheWriteTokens` (tokens written to it), both part of `inputTokens`. Validation keeps them and rejects a `cacheReadTokens` + `cacheWriteTokens` sum above `inputTokens`.
- Library exports `LLM_ERROR_KINDS`, `isLlmErrorKind` and the type `LlmErrorKind`. `CanonicalEventType` includes `'llm.failed'`.
- SDK usage parameters: Python `usage()` and the legacy `llm_usage()` take the keyword-only `cache_read_tokens`, `cache_write_tokens`, `currency` and `task_id` (`llm_usage()` also `reasoning_tokens` and `request_id`); TypeScript `UsageOptions` takes `cacheReadTokens`, `cacheWriteTokens`, `currency` and `taskId`, and the token fields, `costSource` and `currency` accept `null`. `currency` is forwarded as given, with no default, and `task_id` / `taskId` goes to the envelope `taskId`. The TypeScript SDK exports the `CostSource` type, and its usage payload is typed against the contract, so a renamed contract field fails `npm run lint`.
- Server usage aggregates, computed call by call by one pure reducer (`server/usageAggregates.ts`): every `llm.usage` call is added to the total, to its agent and to the `(provider, model)` of the call itself, so switching models never moves past calls. Failed calls (`llm.failed`) are counted apart under `failed`. Unknown stays visible: each token kind has a `sum` that is `null` until a call reports it, plus `unreportedCount`; cost is kept per `(currency, costSource)` pair in exact fixed point, with `costMissingCount` and `currencyMissingCount` for calls that cannot be priced. Nothing is priced, converted or summed across currencies. Guide: [Usage aggregates](docs/integration.md#usage-aggregates-get-apiv1usage).
- `usage` block in `GET /api/v1/snapshot` and new `GET /api/v1/usage`, which returns the same `UsageSummary` without the event list (same token and rate limits as the rest of `/api/v1`).
- Ingestion integrity: every event gets a content `fingerprint` (`sha256:` over the event as validated, keys sorted, defaults filled in, computed by `server/eventFingerprint.ts`), so a repeated id is told apart by content. Same id and same content is a duplicate (`200`, as before); same id and different content is the new `409 conflicting_duplicate`, and that event is not stored, not aggregated and not streamed. The `202`, `200` and `409` bodies include `fingerprint` (and `storedFingerprint` for a conflict).
- `POST /api/v1/events` answers `400 idempotency_key_mismatch` when the `Idempotency-Key` header and a non-empty body `id` differ, instead of silently ignoring the header. A header with no body `id` still becomes the id.
- `POST /api/v1/events/batch` results carry `status` (`accepted`, `duplicate` or `conflict`) and `fingerprint` per item, plus `error` and `storedFingerprint` for a conflict, and the response adds a `conflicts` count. The status stays `202` when validation passes, even if every item is a conflict. The generic webhook response adds `duplicateCount` and `conflictCount`.
- `GET /ready` reports `ingestion: { conflicts, legacyUnverifiedDuplicates }` since the process started, and each conflict writes one `warn` log line with the id, type, source, agent id and both fingerprints (never the payload).
- SQLite migration 2 (`content-hash`) adds `events.content_hash` and backfills it from `event_json`. Rows written before 0.2.0, or with unreadable `event_json`, keep `NULL`: a repeated id that matches one is treated as a duplicate, counted in `legacyUnverifiedDuplicates` and warned about once per process.
- SDK `AgentViewerError` has a `code` (the response body `error`): check `err.code === 'conflicting_duplicate'` in TypeScript or `err.code == "conflicting_duplicate"` in Python. Neither SDK retries a 409. TypeScript `emitBatch()` returns `{ accepted, duplicates, conflicts, results }` with each item's `status` (`conflicts` is `0` against a 0.2.x server); Python `emit_batch()` returns the server response, which now has them too.
- TypeScript SDK `usageSummary()` and Python SDK `usage_summary()`. The TypeScript SDK types `snapshot()` as `Promise<ViewerSnapshot>` and exports `UsageSummary`, `UsageAggregate`, `UsageBucket`, `ModelUsage`, `AgentUsage`, `TokenFigure`, `CurrencyCost` and `ViewerSnapshot`.
- `docs/usage-semantics.md` and `docs/usage-semantics.es.md`: the single binding reference for what a token or cost figure means at every layer (rules U1 to U5, the `llm.usage` field reference, unknown versus zero, currencies, `costSource`, cache read versus write, `llm.failed`, deduplication, what a total covers, where each on-screen figure comes from, and how to reconcile against an invoice).

### Changed
- `RealtimeStatus` gains a new member, `resyncing`. Additive, but a host with an exhaustive `switch` over the union gets a TypeScript error and needs to handle it. Against a server without the new SSE frames (0.2.x), `connectEventStream` behaves exactly as before.
- A reconnect that misses more events than `AGENT_VIEWER_SSE_REPLAY_MAX` (or whose cursor is unknown) no longer silently replays "the newest 100" events (wrong events entirely for an unknown cursor, a hidden hole in the middle of the history otherwise, issue #54). Gaps up to the limit are now replayed in full instead of capped at 100. A 0.2.x client that ignores the new named frames gets no warning about the gap; upgrade the helper to see it.
- `GET /ready` answers `503` with `Retry-After: 1` and a `rebuild` object while a SQLite-backed server replays its stored events at startup, then `200` once the replay finishes. `GET /health` keeps answering `200` the whole time. While the rebuild runs, `GET /api/v1/snapshot`, `GET /api/v1/runtimes`, `GET /api/v1/sessions`, `GET /api/v1/sessions/:id`, `POST /api/v1/agents`, `PATCH /api/v1/agents/:id` and `POST /api/v1/runtimes` answer `503 store_rebuilding`; `POST /api/v1/events` and `/events/batch` stay open and are applied once the rebuild reaches them. Memory storage is unaffected: `/ready` answers `200` immediately.
- `PATCH /api/v1/agents/:agentId` now emits an `agent.updated` event for any changed profile field (name, roleTitle, role, provider, model, workspace, statusText), not only for a status change. `POST /api/v1/agents` and `POST /api/v1/runtimes` now put every resolved default in their event payload (`agent.registered`, `runtime.connected`), so the state a startup rebuild reaches from stored events matches the live response exactly. Event ids built by these three routes now include a random suffix, so two changes to the same id in the same millisecond are never deduplicated against each other. SQLite migration 4 (`events-seq`) adds a durable insertion-order column (`events.seq`), backfilled from `rowid`; the startup rebuild and the `afterId` cursor use it instead of `rowid`, which SQLite can renumber on `VACUUM`.
- Docker Compose now publishes the API and viewer ports on `127.0.0.1` only. To restore network-wide publishing, change the mappings back to `"8787:8787"` and `"3000:3000"`, update `AGENT_VIEWER_CORS_ORIGIN` and `VITE_AGENT_VIEWER_API_URL`, and put the services behind TLS. The plain server's listening log now accurately says it listens on every interface instead of suggesting `localhost`.
- Model Ops' simulator types: `SimulatedTokenBurst` and `InferenceLogItem` are replaced by `SimulatedCall` (`src/engine/modelOps.ts`), always carrying `simulated: true`, an `estimatedCost`/`currency` that are `null` for an uncatalogued model, and living outside `SimulationState` (never persisted, exported or counted). `calculateModelCost` now returns `number | null` instead of always pricing against GPT-4o's rate. These are demo-app internals, not part of the published `@warlockcode/agent-viewer` library API, so there is no semver impact on the package.
- Webhook generic route now produces deterministic event IDs instead of random ones when an idempotency key is detected. IDs have format `evt_wh_<kind>_<32-char-hex>` (SHA-256 based, do not reveal the key or signature) and match the same collision-free guarantee as server ids. Deliveries with no idempotency key get server-generated random ids and are marked as `source: "none"` (not safe to retry).
- Webhook responses add `duplicate` (true only when every event is a duplicate), `duplicates` (count of duplicate events), `idempotency` (object with `source`: `body`, `header`, `signature`, `requestId`, or `none`), and a `results` array with per-event `duplicate` flag.
- Same delivery by signature now gets `200` with `duplicate: true` instead of `409 webhook_replay_detected`, because the signature cache now records the delivery after store success, not before validation.
- Webhook responses change conflict handling: `409 event_id_conflict` is returned when any event conflicts (same id, different content), `200` when all are duplicates, `202` when at least one is new. Conflicting batches are stored atomically: all or nothing.
- `express` is now a runtime dependency (the CLI runs the server from the installed package). `dotenv` stays a development dependency: the server loads `.env` only when run directly.
- `startServer(port, host?)` accepts the interface to bind, and `onEventAccepted(listener)` reports every accepted event of the six ingestion paths (never a duplicate). A listener that throws or returns a rejected promise never breaks ingestion.
- `--record` creates its file readable only by the owner (mode 0600), stops the CLI before it listens when the path cannot be written, and on a write error mid-run (full disk) stops recording with one warning while the server keeps running.
- `connectEventStream` (library export) sends `token` in an `Authorization: Bearer` header over a streamed `fetch`, with the `token` query parameter only as a fallback, and accepts a `fetch` option.
- The package declares `engines.node >=22.13`.
- CI builds the CLI, runs it from the packed tarball and builds both Docker targets.
- `normalizeCanonicalEvent` (used by the library and the generic webhook) no longer invents `inputTokens: 0` or `outputTokens: 0` for `llm.usage`, keeps `llm.failed` instead of rewriting it to `agent.status.changed`, and sets an unlisted `llm.failed` `errorKind` to `unknown`.
- Exhaustive `switch` statements over `CanonicalEventType` in host TypeScript code must handle `'llm.failed'`.
- `summarizeUsage` (correctness fix, same types): it counts each event `id` once (the first occurrence wins, whatever its type or agent; events without an id are each counted, the same object only once), so repeated events from reconnects, retries or merged replays are no longer counted twice. A token count that an event does not report as a non-negative integer makes that figure unknown (`null`) instead of adding `0`, and `totalTokens` is known only when input and output tokens are. The cost is `null` when events report different ISO 4217 currencies, when an ISO currency is mixed with a cost without a valid currency (such as `'usd'` or none), or when a cost is negative, non-finite or text; `currency` is set only when the cost is known. Some figures that were numbers are now `null`, and some totals are lower because duplicates no longer count. Migration: if you relied on missing token counts being treated as 0, send explicit `0` values in your `llm.usage` events.
- Example adapters (`examples/`) no longer fill unknown token counts with `0` and no longer infer `provider-reported` from the presence of a cost. The OpenAI Agents, LangGraph and CrewAI adapters take the cost source as an argument (default `unknown`), and a cost of `0` is kept.
- `llm.usage` calls without an agent (from `runtime:*`, `system` or `external-runtime`) now count in `totalTokens` and in `usage.total` under `agentId: null`; they were dropped before. Per-agent token fields are unchanged for well-formed events.
- Server-generated event ids (agent registration, `PATCH` status and profile changes, runtimes and the generic webhook) are `evt_<kind>_<uuid>` from `crypto.randomUUID()`, for example `evt_reg_0b9f1c2e-...`, instead of the agent or runtime id plus `Date.now()` (and `Math.random` for webhooks). Two requests in the same millisecond used to produce the same id: the second event was dropped as a duplicate but still streamed, so the office showed something the store never kept. Now each request stores and streams its own event, and a server-generated id that is not accepted is logged at `error` and answered with `500 internal_id_collision` instead of being hidden. Nothing parsed the old id format.
- Default event ids are 128 random bits: `evt_<uuid>` in the TypeScript SDK (was the clock plus `Math.random`), `evt_<32 hex>` in the Python SDK (was 12 hex characters, 48 bits), and `evt_<uuid>` from `normalizeCanonicalEvent` where `crypto.randomUUID` exists (older browsers keep the previous fallback).
- A batch that repeats an id reports `duplicate: true` for the dropped copy; both copies used to report `duplicate: false`.
- With SQLite, a batch is stored all or nothing (`BEGIN IMMEDIATE ... COMMIT`, rolled back on any error), and the in-memory aggregates are fed only after the commit, with the accepted events. A failure part way through used to leave a partial batch on disk.
- SQLite migrations skip the pre-migration backup when the `events` table has no rows yet. This also keeps a server that starts while another one is migrating a fresh file from writing a backup of it.
- The server store no longer accepts usage figures outside stored events: `upsertAgent` ignores `tokensInput`, `tokensOutput`, `cachedTokens`, `reasoningTokens` and `cost` (its input type no longer has them), so usage fields sent to `POST` or `PATCH /api/v1/agents` never move a figure. See Breaking changes above for the `PATCH` allow-list itself.

### Deprecated
- `llm.usage` `cachedTokens`: send `cacheReadTokens` instead. It is still accepted, kept as sent and copied into `cacheReadTokens` when that field is absent; a different number in both fields is rejected at `payload.cachedTokens`.
- Snapshot `totalTokens` and `totalCost`, and the `AgentRecord` usage fields `tokensInput`, `tokensOutput`, `cachedTokens`, `reasoningTokens` and `cost`: read `usage` (or `GET /api/v1/usage`) instead. The token fields are sums of reported values only, so they are lower bounds when some call did not report a kind. They will be removed in 1.0.

### Fixed
- SQLite-backed server state (agents, runtimes, sessions, tasks, meetings and usage totals) no longer resets to empty on restart. At startup the server now replays every stored event, in insertion order, through the same reducer the live path uses, so the state after a restart is identical to the state before it. An upgrade that changes the reducer recomputes the whole history with the new reducer at the next startup; that is intended, not a bug.
- A retried `llm.usage` or `llm.failed` event (or any event id) that had already fallen off the memory-mode retained window is no longer double counted. Before this fix, eviction deleted the id from the dedup index too, so a late retry (a timeout retry, an SDK queue flush, a webhook redelivery) was accepted as new: its tokens and cost were added a second time to the agent and global totals, and it was broadcast again. The fix only changes behavior for an id that had already fallen out of the retained window; an ordinary retry of a still-retained event was already deduplicated correctly.
- Model Ops no longer shows simulated calls as if they were real usage. The hard-coded "Live inference feed" seed rows (`Elena Rostova`, `Kenji Sato`, `Dr. Maya Chen`) are gone, and every simulator trigger (header quick-burst, per-provider quick request, per-model simulate, the Simulator tab's fire button, feed "Send request") now only records a `SimulatedCall`, tagged with a visible `SIMULATED` / `SIMULADO` chip; it never touches an agent's token or cost counters, the office totals, or `state.events` (no more fake `llm.usage` events). In live mode, the four buttons that used to inject fake usage into a real agent are not rendered; the Simulator tab stays available as a labelled what-if calculator with a persistent banner, and the Agents tab's model reassignment is disabled (the portal cannot change a remote agent's model).
- A model the demo catalog does not know is no longer priced and labelled as GPT-4o. `calculateModelCost` and the new `getModelSpec` have no fallback: an uncatalogued model (for example a live agent's real `claude-sonnet-4-5`) shows its own id, "Not in the demo catalog", and "Unknown" instead of GPT-4o's name, context window and per-1M rates. The Simulator tab shows "Rate: unknown" and "Estimated cost: Unknown" for it.
- New Task no longer invents usage in live mode: `triggerCustomTaskSimulation` takes a `countUsage` option, and the demo app passes `countUsage: false` in live mode, so submitting the dialog creates the task without adding any token or cost figure to the target agent or to the office totals. Demo mode behavior (`countUsage: true`) is unchanged.
- A v1 demo session (0.2.x) saved with a `evt-burst-*` simulated event now migrates to v2 on load: the event is removed and its token/cost values are subtracted from the agent and from the office totals, clamped at 0. Sessions already evicted past the stored event cap cannot be reversed and keep their old counters, a known limitation. A v2 session loads unchanged.
- Webhook usage retries no longer double-count. The generic webhook now uses deterministic event IDs derived from idempotency keys, so identical retries are deduplicated inside the store. Same delivery with same `Idempotency-Key` header, body `idempotencyKey` field, or signature gets a `200` duplicate response instead of `202` new events. A sender that re-signs a retry needs to include `idempotencyKey` in the body for the same effect.
- Webhook usage no longer drops `currency`, `costSource`, `requestId` and the cache fields. Validation now uses the same `LlmUsagePayloadSchema` as the events API, and these fields are kept exactly as sent.
