### Application integration

- `src/engine/officeCrewAssets.ts`: the main viewer can load static Office Crew artwork; mapping role, facing, clip and foot-anchor works with the manifest. It supports frameFiles/FPS metadata but had no import glob for a separate runtime animation directory at the audited SHA.
- `src/engine/visualMotion.ts`: move between positions at a bounded speed. Translating an idle image or applying bobbing does **not** make a true walking cycle.
- `src/visual-studio/scene.ts`: **illustrative** 44-second scene in director, meeting, coffee, simulated call, TV news and path traversal. This scene is not proof that every operational room in `src/engine/canvasRenderer.ts` was refurbished.
- `src/components/OfficeCanvas.tsx`, `src/engine/canvasRenderer.ts`: Canvas2D integration and non-breaking procedural fallback. Do not mutate event, usage or tasks from the visual layer.
- `tests/lib/officeCrewAssets.test.ts`: tests sprite loading, bounds, rotation, fallback and timing; not tests of fidelity to illustrated CEO or real hand/leg articulation.

## Confirmed technical gap from source inspection

The original `scripts/validate-visual-assets.mjs` walked obsolete room names `assets/rooms/<room-id>.json`, while actual room layouts live under `assets/rooms/<room-id>/layout.json`. This silently skipped layout checks. The original `officeCrewAssets.ts` bundled `assets/characters/*/*` but did not include future production frames from `assets/animations/**`.

This recovery branch fixes both and adds validation of per-frame runtime PNG dimensions/alpha and clip frame content plus tests for looping/reduced-motion. **These pipeline changes do not add any final CEO raster frames.**
